# Model card — orbis-edge-risk 1.0.0

> Generated by `python -m orbis_ml card` from the evaluation, parity, benchmark, adversarial and reproducibility reports in this directory. Measured values only; targets are labelled as targets.

## Model details

- **Task:** 4-class risk classification of one canonical endpoint event (`edge-features/1`, 85 features): `safe_normal`, `safe_unusual`, `suspicious_review`, `high_risk`.
- **Architecture:** mlp-32x16 — dense ReLU MLP, 3348 parameters, outputs logits.
- **Calibration / decision policy:** temperature T = 0.912089, τ_review = 0.24 on P(suspicious)+P(high), τ_high = 0.88 on P(high); abstain on unknown schema fields or normalised entropy ≥ 0.9; abstained high-impact actions are escalated. Versioned separately as `1.0.0+cal1`.
- **Authority:** advisory only. Deterministic tenant policy owns authorization; the model may raise review, never lower it, and is ignored when unavailable, stale, incompatible or out of distribution.
- **Owner:** Orbis Relay ML. **Selected by:** lowest validation security cost among portable models (see `../baselines_report.md`).

## Intended use

Score sensitive actions proposed by AI agents, automations and people *before* they execute, on the endpoint (Core ML) or in the gateway (TypeScript port), so policy can route ambiguous or high-risk actions to a verified human with an explanation.

## Out of scope

- Final allow/deny decisions, DLP content inspection, malware detection, user surveillance.
- Raw content or raw destinations: the model only sees metadata and 16-hex destination hashes.
- Tenants or action vocabularies outside `endpoint-event/1` — those events abstain and fall back to policy.

## Training data

- **Base dataset:** `northstar-actions@1.0.0` — 33,274 synthetic Northstar Cloud events over 28 days, 49 actors, 73 scenario templates; seed 20261005; generator config `ecc09905e525…`.
- **Train split:** 17,489 rows (high_risk 247, safe_normal 15,517, safe_unusual 815, suspicious_review 910). Intentionally imbalanced; hard negatives 1,012, adversarial 848.
- **Splits:** time-based (days 0–17 / 18–22 / 23–27), whole actor instances held out of train/val, template variant v2 and the disguised-classification template only in test. Leakage checks: pass.
- **Label noise:** 1% weak-label flips between the two safe classes (documented, kept in every split).

## Known limitations

- **Misclassified data defeats it.** If the event says `internal` and the payload is secret, a metadata model cannot know (gold g-k01/g-k02, test-only template). Classification must come from DLP/policy, not the agent.
- **Slow ramps are absorbed** by per-actor baselines (g-k03); the drift monitor is the complementary control.
- **Synthetic data.** Every training and test event is generated; real-tenant performance is unknown until shadow mode produces reviewed labels.
- **Gold set is no longer fully blind** for one behaviour: an unregistered-tool shortcut was found via a gold failure and fixed in the generator (see `error-analysis.md`).
- **Human feedback is weak supervision.** Approvals can be wrong; proxies are down-weighted and never applied online.
- Adversarial: *disguised classification ('internal') emailed to a new domain* — not caught by the edge model alone.
- Adversarial: *agent-asserted ticket flag on $40k+ refunds* — not caught by the edge model alone.
